# 共享事务系统与两条存储路径（2026-11-04）

此前将本地路径变成只读的改动已纠正。AppleScript、JXA、osascript 仍然禁用；本地写入、AFK 生命周期、监控写回与附件读取已经接回事务系统。

```text
MCP 工具 / 业务操作
        ↓
OmniFocusService：统一业务校验、事务生成、回读
        ↓
OmniFocusStore：统一事务链重建、ZIP/XML、加解密
        ↓
StoreStorage
  ├─ LocalStorage：本地目录枚举、读取、原子发布
  └─ WebDavStorage：PROPFIND、GET、PUT
```

## 路由与兼容

任务查询、详情、计数、项目、标签、文件夹、附件和 13 个普通写入工具均接受 `backend: local | remote`，默认 local。两条路径使用相同的工具处理函数、Service、Store、数据模型与 writer。没有失败自动回退。

本地路径由 `OMNIFOCUS_LOCAL_DATABASE` 指定，默认 OmniFocus 4 容器里的 `OmniFocus.ofocus`。本地明文库不需要远端凭据；加密库使用 `OMNIFOCUS_ENCRYPTION_PASSPHRASE`，兼容以同步密码作为口令。

远端路径沿用 `OMNIFOCUS_SYNC_*` 与 `OMNIFOCUS_OFOCUS_URL` 配置。AFK/监控保持原有本机归属账本与协议，固定关联本地路径，避免把同一归属记录错误地用于另一份数据库。生产 legacy 和 staged v2 都已接到共享事务写入；没有擅自切换生产归属协议。

## 数据与写入行为

- 读取按父事务关系重建历史，支持时间戳逆序与分支。写入连接当前所有末端，不丢弃其他分支。
- 提交前比较读取时的事务列表签名；发现变化则拒绝此次写入，不盲重放。原生应用或远端客户端不受本机进程锁约束，提交后的并发分支由事务协议表达。
- 本地事务先写临时文件并 fsync，再以不覆盖已有文件的原子发布加入目录；不原地改基线或现有事务 ZIP。`.client` 注册文件可以原子更新。
- 共享客户端状态路径的 MCP 写进程使用互斥锁。失败可能已发布事务时，错误明确提示先回读；生命周期保留原有 intent/归属保护。
- 普通任务新增、编辑、标签调整、移动、完成、丢弃/恢复、删除，以及项目/目录/标签和检查周期写入均已恢复。批量检查周期在两种后端都生成一个事务。
- 数据库状态判断覆盖任务/祖先完成与丢弃、项目暂停、目录隐藏、延期、暂停标签、顺序前置及动作组。返回 `statusSource: transaction-database`，不冒称 OmniFocus 原生 API 快照。
- AFK start/done/needs_human 与监控 start/checked/done/needs_human 采用单个标签/备注事务；保留等待，不创建工作流标签，不自动完成动作，保留人类撤回和归属校验。
- 附件元数据来自事务中的 attachment 对象，内容来自存储路径的 `data/<identifier>.zip`。不解压到用户磁盘，不跟随文件系统链接；分页和大小限制保留。

## 仍有的格式边界

共享引擎原本不实现重复任务完成后的下一实例生成，也不实现重复系列的单次丢弃。这两种具体操作仍会在写入前拒绝；普通任务写入正常。不能把“整个系列丢弃”偷偷当成“当前实例丢弃”。

数据库侧可用性属于已实现规则的计算值，不承诺覆盖 OmniFocus 所有偏好项和原生状态枚举（例如 Next/DueSoon 的完整展示语义）。链接文件信息尚未完整建模，`linkedFileCount` 保持 null；不把它当作没有链接文件。

## 后续缺陷检查

- 交接说明允许带已有的“交付：”或“需要你处理：”前缀；写入时只保留一个，历史备注不改写。普通、v2、监控交接及监控错误升级使用一致的处理。
- 交接保留备注原有富文本结构、样式和内嵌单元；无法安全保留时拒绝事务，不退化为覆盖原备注。
- 项目所属目录的中间祖先缺失时，动作判为不可执行；ZIP 中单文件位于子目录时按目录读取。
- 对真实本地库的隔离副本执行新增、编辑、完成、删除并回读验证；源数据库没有参与写入。应用界面与跨设备同步仍未作真实写入验证。

## 真实 WebDAV 同步验证（2026-11-04）

经用户明确授权，在真实本地数据库创建一个唯一临时收件箱动作，用 OmniFocus 工具栏手动同步，再删除该动作并再次手动同步。已分别从 WebDAV 下载并解密创建、删除事务，核对测试 ID；删除事务是创建事务的后代，并位于远端当前事务链上。本地读取确认测试动作已不存在。

边界：创建后及首次手动同步后，正在运行的 OmniFocus 收件箱和搜索中均未显示该测试动作；不能把事务成功上传等同于应用内即时刷新。未验证自动同步、应用重启后的显示或其他设备的最终状态。测试产生两个本地客户端登记文件，远端未发现该测试客户端的登记；它们没有擅自删除，是否需要本地登记还需进一步核实。

### 自动同步与重启补充验证

第二个唯一测试动作从本地事务后端写入后，OmniFocus 保持运行约 67 秒；收件箱没有立即显示该动作，同步日志没有新增记录，远端也没有该创建事务。这个观察只覆盖当次 67 秒窗口，不能推断更长时间内绝不会同步。

按用户指示正常退出并重启 OmniFocus 后，测试动作出现在收件箱，应用产生 `XMLSyncTriggerDatabaseReady` 同步；远端下载并解密的创建事务与测试动作一致。之后从本地事务后端删除该动作：应用在运行中仍暂时显示旧条目；再次正常重启后条目消失，`DatabaseReady` 同步将删除事务上传。确认远端删除事务继承创建事务并处于当前远端事务链，本地测试动作已不存在。

两轮测试累计产生四个 fork 本地 `.client` 文件，其中两个引用第二轮创建和删除事务；远端没有对应 fork 客户端登记。它们没有被自动删除；其存在是否影响原生数据库或未来整理尚未证明。本验证没有覆盖其他设备，也没有证明本地写入可实时通知运行中的应用。

### 界面编辑是否触发加载（2026-11-04）

按用户要求，先通过本地事务后端写入唯一临时动作，再通过 OmniFocus 界面创建另一个唯一临时动作。界面动作可见，数据库直写动作在运行中的应用内仍不可见。界面编辑触发 `XMLSyncTriggerRecentEdit`：本地重建结果包含两个动作，WebDAV 收到两条创建事务。因此界面编辑能触发同步，但本次未触发应用重载之前的外部事务。

随后按精确 ID 清理两个测试动作：数据库测试动作通过本地事务删除，界面测试动作通过 OmniFocus 界面删除；本地两者均不存在，两条删除事务均已出现在 WebDAV。未改写其他任务。

本机 OmniFocus 的脚本定义中，`open` 有 `using cache` 参数，说明设为 false 可在打开文档时重建数据缓存；同一定义提供 `synchronize`。这只是候选机制：对于已经打开的主数据库，`using cache: false` 是否会重新加载，以及是否需要关闭文档，尚未执行脚本验证。已确认的重启方案和 UI 写入触发同步的观察不等于该候选已验证。`Rebuild Database` 会检查并整理数据，不应作为普通刷新按钮盲目使用。

### 新建窗口是否触发加载

通过本地事务后端再创建一个唯一临时动作，随后在仍运行的 OmniFocus 中使用“文件 → 新建窗口”。窗口菜单确认存在两个窗口，但新窗口收件箱仍未显示该动作；新建窗口不构成已观察到的刷新方案。已关闭测试窗口，精确删除临时动作，并确认创建和删除事务均已到达 WebDAV。
